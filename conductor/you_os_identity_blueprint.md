# ملف هوية واجهة YOU OS / ZiqaKernel

**النسخة:** 0.1  
**التاريخ:** 2026-07-04  
**الغرض:** حفظ هوية الواجهة الخاصة بالنظام: المؤشر، التوب بار، الدوك، سطح المكتب، طريقة عرض النوافذ، والتوجه التنفيذي الآمن.

---

## 1. الرؤية العامة

نظام YOU OS / ZiqaKernel لا يجب أن يبدو كنسخة من Windows أو GNOME أو macOS. الهوية المقترحة هي **Nucleus Shell**: واجهة هادئة، تقنية، واضحة، وفيها لغة بصرية واحدة تتكرر في كل مكان.

الفكرة المركزية:

> النظام ليس مجرد نوافذ ودوك ومؤشر؛ النظام مساحة عمل فيها “نواة تفاعل” تظهر في المؤشر، النافذة النشطة، الدوك، والتوب بار.

المبادئ:

- واجهة عصرية بدون مبالغة.
- وضوح قبل الجمال.
- ثبات الرندرة قبل الأنيميشن.
- كل عنصر يجب أن يكون مفهومًا للمستخدم العادي.
- الهوية البصرية يجب أن تكون قابلة للتطبيق داخل Rust/Orbital/BGA بدون مكتبات ثقيلة.
- لا يتم تقليد الأنظمة الأخرى، لكن لا نكسر الأشياء المفهومة مثل minimize/maximize/close.

---

## 2. مؤشر النظام: Ziqa Nucleus Cursor

أقوى فكرة في الهوية هي المؤشر. لا يكون سهمًا قديمًا عمره عقود، ولا يكون مجرد شكل غريب. المؤشر يكون **نواة دقيقة + مجال تفاعل**.

### الوصف البصري

الشكل الأساسي:

```text
      •
   •  ◆  •
      •
```

- `◆` هي نقطة الدقة / hotspot.
- النقاط حولها هي field يوضح حالة التفاعل.
- المؤشر يجب أن يظهر فوق كل شيء كـ overlay compositor، وليس كجزء من النافذة أو سطح المكتب.

### الحالات المستقبلية

- **Normal / Explore:** ماسة بيضاء صغيرة مع نقاط هادئة.
- **Hover / Magnet:** المجال يتمدد باتجاه العنصر القابل للضغط.
- **Pressed / Pulse:** النواة تنكمش وتعود بسرعة.
- **Text / Gate:** تتحول إلى بوابة نصية بدل I-beam التقليدي.
- **Drag / Grip:** أربع نقاط حول النواة توحي بالإمساك.
- **Loading / Orbit:** نقطة تدور حول النواة.
- **Not Allowed / Collapse:** المجال ينهار مع شكل منع واضح.
- **Resize X/Y:** شكل هندسي واضح لتغيير الحجم.

### قاعدة التنفيذ الحالية

قبل إضافة الشكل الجميل، يجب تثبيت pipeline المؤشر:

1. إيقاف أي رسم Nucleus غير مستقر مؤقتًا.
2. اختبار مؤشر debug صغير يتحرك 30 ثانية بدون freeze.
3. منع أي rect سلبي أو خارج الشاشة.
4. جدولة old_rect ∪ new_rect بعد clipping.
5. إعادة رسم الخلفية/النوافذ تحت المؤشر أولًا.
6. رسم المؤشر آخر طبقة.
7. بعد ثبات الحركة، نعيد Nucleus Cursor.

### المخاطر التي ظهرت

- المؤشر علق في الزاوية العلوية.
- ظهر له مربع/canvas خلفه.
- ترك ghost/trail أثناء الحركة.
- بعد الترقيع تجمدت الواجهة بعد ثوان.

التفسير الأقرب: cursor_x/y بين hotspot وtop-left غير موحد، أو cursor_rect سالب قرب الزاوية، أو dirty/sync rect خارج الشاشة.

## 3. التوب بار: Nucleus Top Rail

التوب بار ليس مجرد شريط. هو مركز النظام الهادئ.

الشكل المقترح:

```text
┌──────────────────────────────────────────────┐
│ ◆ ZiqaOS           [ Desktop ]       UP 02:14 │
└──────────────────────────────────────────────┘
```

### اليسار

- علامة نواة صغيرة `◆` بجانب ZiqaOS.
- تمثل مركز النظام.

### الوسط

- يعرض اسم النافذة النشطة أو `[ Desktop ]`.
- يوضع داخل capsule أو نص مركزي نظيف.
- لا يبدأ من منتصف الشاشة بلا قياس؛ يجب تجنب overlap مع اليمين واليسار.

### اليمين

- uptime أو الساعة أو system status.
- لاحقًا يمكن إضافة network/audio/battery.

### قواعد التصميم

- استخدام config colors، لا hardcoded colors.
- لا نملأه بتفاصيل كثيرة.
- يبقى بسيطًا، واضحًا، ومرتبطًا بلغة النواة.

## 4. الدوك السفلي: Nucleus Dock

الدوك هو مرسى التطبيقات، وليس مجرد مربعات ملونة.

الشكل:

```text
        ╭────────────────────────────╮
        │  ◈ Terminal   ◈ Files   ◈ Settings │
        ╰────────────────────────────╯
```

### حالات الأيقونة

- **لا نقطة:** التطبيق مغلق.
- **• نقطة صغيرة:** التطبيق مفتوح أو مصغر.
- **◆ ماسة صغيرة:** التطبيق هو النافذة النشطة.
- **◌◆◌ field:** المؤشر فوق الأيقونة.

### منطق الدوك

- إذا التطبيق مغلق: click = launch.
- إذا التطبيق مفتوح ومصغر: click = restore.
- إذا التطبيق مفتوح وغير نشط: click = focus.
- إذا التطبيق نشط: click يمكن أن يقلله لاحقًا أو يبقيه نشطًا.

### التصميم

- hover يكون field/halo خفيف، لا مستطيل قاسٍ.
- running indicators يجب أن تكون dots/diamonds، لا مربعات 4×4 واضحة.
- لا أنيميشن في البداية حتى يثبت المسار.

## 5. سطح المكتب: Nucleus Desktop Background

سطح المكتب ليس wallpaper عادية. هو خلفية نظامية هادئة.

### الطبقات

1. لون داكن تقني.
2. gradient بسيط أو diagonal/vertical stripes خفيفة.
3. grid خفيف جدًا كل 32px أو 48px.
4. نواة/diamond كبيرة منخفضة التباين في الخلف.
5. نقاط static منخفضة الشفافية.

### الشكل العام

```text
┌──────────────────────────────────────────────┐
│ ◆ ZiqaOS                         UP 00:42    │
├──────────────────────────────────────────────┤
│        .             .                       │
│              ◌                               │
│                    ◆                         │
│              .                               │
│                                              │
│              [ windows appear here ]         │
│                                              │
│          ╭────────────────────╮              │
│          │ Terminal Files ... │              │
│          ╰────────────────────╯              │
└──────────────────────────────────────────────┘
```

### قواعد التنفيذ

- لا blur الآن.
- لا particles animated.
- لا PNG/wallpaper engine.
- لا مكتبات رسم جديدة.
- primitives فقط: rect/line/dot/diamond.

## 6. عرض البرامج: Nucleus Window Cards

النوافذ تظهر كبطاقات نظامية، وليست مستطيلات خام.

الشكل:

```text
╭─ ◆ Terminal ───────────────────── — ◇ × ╮
│                                          │
│                Content                   │
╰──────────────────────────────────────────╯
```

### النافذة النشطة

- علامة `◆` بجانب العنوان.
- titlebar أو border أقوى قليلًا.
- accent edge خفيف.
- تظهر كأنها “ممسوكة” من النظام.

### النافذة غير النشطة

- titlebar أغمق أو أهدأ.
- border أقل وضوحًا.
- لا mark قوي.

### أزرار النافذة

- `—` تصغير.
- `◇` تكبير/استعادة.
- `×` إغلاق.

هذه الرموز مفهومة، لكن `◇` يربط النافذة بلغة النواة.

## 7. التصغير والتكبير والاستعادة

### التصغير Minimize

عند ضغط minimize:

- تختفي النافذة من سطح المكتب.
- تبقى موجودة في state/order.
- يظهر لها indicator في الدوك.
- click على الدوك يعيدها.

### التكبير Maximize

Maximize لا يعني fullscreen. النافذة تملأ workspace فقط:

```text
workspace = screen - top_bar - dock_reserved_area
```

لا تغطي التوب بار ولا الدوك.

### الاستعادة Restore

عند تكبير نافذة:

- احفظ rect القديم في restore_rect.
- عند restore، تعود لنفس المكان والحجم.

### Fullscreen لاحقًا

Fullscreen حالة مختلفة لاحقًا:

- يخفي shell أو يتجاوز التوب بار/الدوك.
- لا نطبقه في المرحلة الأولى.

## 8. App Switcher لاحقًا

ليس ضمن المرحلة الأولى، لكنه جزء من الهوية المستقبلية.

```text
╭────────────────────────────╮
│        Switch Apps          │
│                             │
│  ◆ Terminal                 │
│  ◇ Files                    │
│  ◇ Settings                 │
╰────────────────────────────╯
```

يجب أن يتبع نفس لغة النواة: active = ◆، inactive = ◇.

## 9. قواعد التنفيذ الصارمة

أسلوب التنفيذ المطلوب هو Ponytail/minimal-change:

- افحص أولًا.
- لا rewrite.
- لا refactor واسع.
- لا تلمس ملفات غير مرتبطة.
- لا تضف dependencies إلا عند الضرورة القصوى.
- لا تدخل Zig hotpaths قبل ثبوت Rust implementation.
- تحقق دائمًا بـ cargo check ثم make run-gui.
- لا تقبل “build passed” كدليل بصري.
- أي تغيير بصري يجب أن يتم اختباره في QEMU/VNC لمدة كافية.

### ممنوع لمسها أثناء شغل واجهة الديسكتوب

- cursor pipeline إذا لم تكن المهمة تخص المؤشر.
- render-loop pacing في `core/mod.rs`.
- BGA/framebuffer.
- `ps2_mouse.rs`.
- ABI/Redox bridge.
- input forwarding.
- kernel scheduler.
- window ordering إلا للقراءة أو تغيير صغير مثبت.

## 10. خارطة الطريق

### المرحلة 1: تثبيت المؤشر

- cursor debug صغير.
- لا freeze.
- لا ghost.
- لا square.
- clipping صحيح.

### المرحلة 2: نافذة حقيقية

- minimize/restore.
- maximize/restore.
- active/inactive titlebar.
- dock restore/focus.

### المرحلة 3: Nucleus Dock

- running dot.
- focused diamond.
- hover field.

### المرحلة 4: Nucleus Top Rail

- logo mark.
- focused title capsule.
- status capsule.

### المرحلة 5: Nucleus Desktop Background

- grid.
- subtle gradient.
- large faint nucleus.

### المرحلة 6: إعادة المؤشر النهائي

- بعد ثبات pipeline فقط.
- states تدريجيًا.
- لا animation حتى يثبت الشكل الثابت.

---

## 11. الجملة التي تلخص هوية النظام

> YOU OS ليس سطح مكتب تقليديًا بسهم ونوافذ ومربعات؛ هو Shell مبني حول نواة تفاعل: المؤشر نواة، النافذة بطاقة، الدوك مرسى، والتوب بار مركز حالة هادئ.
